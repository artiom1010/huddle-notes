# Для разработчиков

## Как устроен код

Определение, кто говорит (плитки, аватарки, голоса), включается настройкой
`HUDDLE_SPEAKERS=on`; по умолчанию оно выключено, и расшифровка — текст без имён: абзацы
по паузам, видео не разбирается. Модули с пометкой «имена» работают только при `on`.

| Модуль (`huddle_notes/`) | Что делает |
|---|---|
| `domain.py` | данные звонка: слова, группы аватарок, реплики |
| `speakers/tiles.py` | имена: поиск подсвеченной плитки на одном кадре; своя верхняя рамка, если обвод ушёл в соседа |
| `speakers/detector.py` | имена: плитки по всему видео → группы по аватаркам (`speakers.json`); плитки в движении отбрасываются |
| `transcribe.py` | запуск whisper.cpp (язык звонка, VAD) и чтение его ответа |
| `vad.py` | VAD: таблица из журнала whisper.cpp, которая возвращает слова на их время в записи |
| `voices.py` | имена: отпечатки голосов (sherpa-onnx) |
| `people.py` | имена: база аватарок и голосов команды |
| `attribution.py` | имена: кто сказал каждое слово: плитка → аватарка → голос → «?» |
| `render.py` | один документ на звонок (Заметки + Расшифровка), абзацы без имён, отчёт |
| `pipeline.py` | один звонок целиком; каждый шаг сохраняет результат и продолжает после сбоя |
| `notes.py` | заметки: расшифровка → `claude -p` (без инструментов, в пустой папке) → Markdown; свои правила для расшифровки с именами и без |
| `deliver.py` | сообщение в Slack: название звонка, имя файла записи, файл (с именами — вопрос про неузнанных); отказ после трёх попыток |
| `feedback.py` | пожелания к заметкам (`пожелания.md`): ответы в треде под сообщениями бота, вопрос на 👎 |
| `watch.py` | наблюдатель за «Записями»: файл перестал расти → обработать → отправить; журнал; повторы (запись, сообщение, заметки); раз в 5 минут — отзывы из Slack |
| `notify.py` | уведомление Windows «Взял в работу» при взятии новой записи: Windows PowerShell 5.1, скрипт и текст в base64 (имя файла не искажается); имя «Huddle Notes» — ключ в реестре пользователя, без него — под именем PowerShell |
| `regression.py` | имена: проверка, что новая версия называет людей так же, как принятая |
| `models.py` | каталог моделей: файлы, ссылки, контрольные суммы |
| `config.py` | все настройки из окружения (`.env`), проверка до начала работы |
| `cli.py` | команды и сборка объектов; больше никто не читает окружение |

Внешние программы (ffmpeg, whisper) запускаются списком аргументов, без shell, с
ограничением по времени. Имена людей никогда не становятся путями к файлам.

## Схема в README

`docs/flow.svg` нарисована из `docs/flow.mmd` (Mermaid 11, цвета и отступы заданы в первой
строке файла). Картинкой, а не блоком Mermaid, — чтобы на GitHub схема выглядела ровно так же.
После правки `flow.mmd` перерисуйте картинку, например в mermaid.live → Download SVG.

## Настройки

Все настройки — переменные окружения, на сервере они в файле `.env`. Полный список с
пояснениями — в [`.env.example`](../.env.example). Модели выбираются там же, каталог
вариантов — в [`huddle_notes/models.py`](../huddle_notes/models.py).

Данные лежат вне репозитория, в `HUDDLE_DATA_DIR`:

```
data/
  people/        avatars.json, voices.json, faces/   ← биометрия, только с HUDDLE_SPEAKERS=on
  glossaries/    <имя>.txt — словарь для whisper: имена, проекты, термины команды
  пожелания.md   пожелания команды к заметкам (из Slack и Claude Code), 40 последних идут в запрос
  slack-feedback.json  какие ответы в тредах уже прочитаны и где бот уже спросил про 👎
  models/        файлы моделей (huddle-notes models download)
```

## Бот в Slack

Приложению `@ai-recap` нужны права бота: `chat:write` и `files:write` — присылать
результат и отвечать в треде, `channels:history` и `groups:history` — читать ответы под
своими сообщениями в открытом и закрытом канале, `users:read` — имена тех, кто ответил. Бот
должен быть участником канала. Свой бот делается так же: приложение Slack с этими правами.

Один канал — одна установка: `SlackFeedback` берёт все сообщения своего бота с файлом в
канале, не только отправленные этой установкой. Две установки с одним ботом в одном канале
записали бы чужие ответы себе и обе ответили бы в треде.

## Запуск на Маке

```bash
brew install ffmpeg whisper-cpp
uv venv --python 3.12.16 .venv && uv pip install --python .venv/bin/python -e ".[dev]"
cp .env.example .env                    # HUDDLE_DATA_DIR — своя папка, HUDDLE_HWACCEL=videotoolbox
set -a; . ./.env; set +a
.venv/bin/huddle-notes models download  # скачивает выбранные модели и проверяет контрольные суммы
.venv/bin/huddle-notes process "запись.mov" --glossary команда
```

Рядом с записью появится папка с одним файлом `ГГГГ-ММ-ДД ЧЧ-ММ.md` и `_work/` (звук,
ответ whisper, найденные плитки). Повторный запуск не пересчитывает готовые шаги.

С `HUDDLE_SPEAKERS=on`: если кого-то не узнали, его лицо будет в папке `Не опознаны`, а в
отчёте — номер группы. Назвать и запомнить:

```bash
.venv/bin/huddle-notes process "запись.mov" --glossary команда --names '{"3": "Вася"}' --learn
```

## Проверки

```bash
.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/mypy && .venv/bin/pytest
.venv/bin/huddle-notes regress <папка эталона>
```

`regress` прогоняет звонки из папки эталона (вне git: там записи и голоса) и сравнивает
расшифровку с принятой. Любое отличие — ошибка. Задуманное улучшение смотрят глазами и
принимают: `regress <папка> --accept`. С `HUDDLE_REGRESSION_DIR=<папка>` эта же проверка
входит в `pytest`.

На GitHub при каждом изменении сами проверяются стиль, типы, тесты, `deploy.sh`, сборка
Docker и случайно попавшие в код токены. Отдельно на Windows: типы кода только для Windows и
`tests/test_notify.py` — Windows сама собирает уведомление из нашего скрипта (не показывая его),
а имя программы записывается в реестр. Как уведомление выглядит на экране, видно только на
компьютере владельца: `huddle-notes notify-test`.

## Как вносить изменения

Ветка → pull request с описанием по-русски → проверки зелёные → ревью → слияние в `main`
→ метка версии (`v0.2.0`) → выкладка.

## Папка для одного человека, без сервера

```bash
scripts/make-package.sh <данные команды> <куда> [<ID канала Slack> [<ID человека в Slack>]]
```

Собирает «Huddle Notes» и «Huddle Notes <дата сборки>.zip» с ней: код (`программа/`),
словари команды (`данные/glossaries`), пустые «Записи» и «Результаты», `.env` из
`package/env.template` и `CLAUDE.md` из `package/` — по нему Claude Code владельца ставит всё
на Windows, включает автозапуск `huddle-notes watch` и отвечает на вопросы. Лиц, голосов и
токенов в архиве нет. Без ID канала архив годится для любого: свой канал и свой ID в Slack
Claude спросит у владельца при установке. Как ставить, для людей —
[docs/install.md](install.md). Архив с вписанными ID передавать владельцу, а не в общую папку.

Новую версию в уже установленную папку — без данных команды:

```bash
scripts/make-update.sh <куда>
```

Получится «Обновление Huddle Notes <дата сборки>.zip», например «Обновление Huddle Notes
2026-11-12.zip»: `программа/` и `CLAUDE.md`. По дате видно, какое обновление новее. Второй
архив за тот же день скрипт не соберёт поверх первого: сначала удали старую папку. Владелец
распаковывает архив и пишет Claude Code в папке Huddle Notes «Обнови программу из папки <путь>».

## Сервер

Работает в Docker, данные в `/srv/huddle-notes/` на сервере:

```bash
docker compose run --rm worker models download
docker compose run --rm worker process /calls/<запись>.mov --glossary команда
```

Выкладка версии — сборка, проверка на эталоне, откат, если что-то изменилось:

```bash
./deploy.sh v0.2.0
```
