# Call Recaps — инструкция для Claude

Эта папка делает заметки и расшифровки Slack-хадлов команды. Ты помогаешь её владельцу:
устанавливаешь всё один раз, отвечаешь на вопросы по звонкам и записываешь пожелания
к заметкам.

```
Call Recaps/
  Записи/       сюда OBS сохраняет видео хадлов
  Результаты/   один файл на звонок: Заметки + Расшифровка; .huddle-notes-journal.json — что обработано
  данные/       словари, модели, work/, logs/; пожелания.md — пожелания команды к заметкам;
                people/ — база лиц и голосов (биометрия), только если имена включены
  программа/    код huddle-notes; не меняй его, пока об этом не попросили
  whisper/      whisper.cpp для Windows (появится при установке)
  .env          настройки и секреты; никогда не показывай токены в чате
```

Как это работает: программа-наблюдатель запускается при входе в Windows, замечает новую
запись в «Записи», делает расшифровку (Whisper), просит Claude Code (`claude -p`, без
инструментов) написать заметки, кладёт файл в «Результаты» и присылает сообщение в Slack:
название звонка, имя файла записи и файл. Примерно раз в 5 минут он читает ответы в треде под своими
сообщениями: каждый ответ становится пожеланием в `данные\пожелания.md`, а бот отвечает в треде
«Записал». На 👎 без слов бот один раз спрашивает в треде, что не так. Пожелания Claude получает
вместе с каждой новой расшифровкой; уже готовые заметки они не меняют. Ответы, написанные до
первого запуска этой версии, пожеланиями не считаются.

Когда наблюдатель берёт новую запись в работу, в углу экрана Windows всплывает уведомление
«Взял в работу» с именем файла: один раз на запись, повторные попытки по тому же звонку идут
без него. Выключается командой `Set-Env HUDDLE_DESKTOP_NOTIFY off` (шаг 6). На этом компьютере его ещё не
видели: проверено только, что Windows собирает его из скрипта программы. Поэтому после
установки или обновления спроси владельца, всплыло ли пробное (`notify-test`).

**Старое имя.** Раньше программа называлась Huddle Notes, и в установках того времени папка,
задача автозапуска в Планировщике и архивы обновлений называются «Huddle Notes». Какая задача
есть на этом компьютере:
`Get-ScheduledTask -TaskName 'Call Recaps', 'Huddle Notes' -ErrorAction SilentlyContinue | Select-Object TaskName`.
В командах ниже подставляй её имя вместо «Call Recaps». Вторую задачу под новым именем не
заводи: две задачи запустили бы два наблюдателя.

**Ты и программа — не одно и то же.** Папку «Записи» проверяет программа-наблюдатель, а не ты.
Заметки пишешь тоже не ты: их пишет отдельный запуск `claude -p` (Claude Code для терминала,
шаг 5). Программа даёт ему расшифровку и инструкцию, он возвращает заметки и закрывается; у
него нет инструментов, и в этот чат он не пишет. Ты за папкой не следишь и первым не пишешь,
только отвечаешь владельцу. Взята ли запись в работу, показывает уведомление; если владелец
спросит тебя, посмотри последние строки `данные\logs\watch.log`: `processing <запись>` — взята.
Следить за логом из чата не предлагай: уведомление делает это само, даже когда чат закрыт.

**Имена говорящих выключены** (`HUDDLE_SPEAKERS=off`, так по умолчанию): расшифровка — текст
со временем, без подписей, кто говорит. Claude просят называть человека в заметках, только
если имя прямо прозвучало в разговоре. Из записи берётся только звук, изображение не
разбирается.

## Установка (один раз, Windows, PowerShell)

Все команды — из корня этой папки. Каждая команда, которую ты запускаешь из приложения Claude,
получает PATH, каким он был при запуске приложения, поэтому только что установленную программу
она может не видеть. Тогда обнови PATH в начале команды (между командами он не сохраняется)
или попроси владельца полностью выйти из приложения Claude и открыть его снова:
```powershell
$env:Path = [Environment]::GetEnvironmentVariable("Path", "Machine") + ";" + [Environment]::GetEnvironmentVariable("Path", "User")
```

1. Инструменты:
   ```powershell
   winget install --id astral-sh.uv -e
   winget install --id Gyan.FFmpeg -e
   ```
   Проверь: `uv --version`, `ffmpeg -version`, `ffprobe -version`.
2. Whisper. Если есть видеокарта NVIDIA (`nvidia-smi` работает), возьми CUDA-сборку,
   иначе обычную. Обе — из релиза whisper.cpp `b5454` (сборка того же дня, что v1.9.5):
   - обычная: https://github.com/ggml-org/whisper.cpp/releases/download/b5454/whisper-bin-x64.zip
   - NVIDIA: https://github.com/ggml-org/whisper.cpp/releases/download/b5454/whisper-bin-win-cuda-12.4.0-x64.zip

   Распакуй в `whisper\` и найди `whisper-cli.exe`. Если CUDA-сборка не запускается
   (не хватает библиотек CUDA), поставь обычную. Если он не прямо в `whisper\`, впиши
   путь: `Set-Env HUDDLE_WHISPER_BIN <путь>` (команда из шага 6). Проверь: `whisper\whisper-cli.exe --help`.
3. Программа:
   ```powershell
   cd программа
   uv venv --python 3.12 .venv
   uv pip install --python .venv\Scripts\python.exe .
   cd ..
   ```
4. Модели (около 1,6 ГБ, контрольные суммы проверяются):
   ```powershell
   программа\.venv\Scripts\huddle-notes.exe models download
   программа\.venv\Scripts\huddle-notes.exe models
   ```
   У моделей whisper и VAD (`silero-v5.1.2`, находит речь, чтобы Whisper не зацикливался на
   тишине) должно стоять `downloaded`. Модель голосов скачивается и нужна, только если имена
   включены (`HUDDLE_SPEAKERS=on`).
5. Claude Code для терминала: через команду `claude` программа пишет заметки. Приложение
   Claude эту команду не ставит. По имени твой терминал её может не найти (см. выше про PATH),
   поэтому вызывай её полным путём `& "$env:USERPROFILE\.local\bin\claude.exe"`.
   Проверь, стоит ли она: `& "$env:USERPROFILE\.local\bin\claude.exe" --version` печатает версию.
   Если нет, поставь:
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
   Скачивается около 350 МБ без индикатора: дай команде до 10 минут. При ошибке
   `SSL/TLS secure channel` добавь в начало команды
   `[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12;`.
   Установщик кладёт `claude.exe` в `%USERPROFILE%\.local\bin`, но эту папку в PATH сам не
   добавляет (пишет об этом в `Setup notes`). Добавь её в PATH пользователя, чтобы владелец мог
   набирать просто `claude`:
   ```powershell
   $p = [Environment]::GetEnvironmentVariable('PATH', 'User'); [Environment]::SetEnvironmentVariable('PATH', "$p;$env:USERPROFILE\.local\bin", 'User')
   ```
   Программе PATH не нужен: она сама ищет `claude` в этой папке.

   **Ключи API.** Если в Windows или в `.env` задан `ANTHROPIC_API_KEY` или
   `ANTHROPIC_AUTH_TOKEN`, `claude -p` возьмёт его вместо подписки. Приложение Claude убирает
   эти переменные из твоих команд, поэтому смотри прямо в настройки Windows и в `.env`
   (печатается только True или False, не сам ключ):
   ```powershell
   foreach ($n in 'ANTHROPIC_API_KEY', 'ANTHROPIC_AUTH_TOKEN') { foreach ($t in 'User', 'Machine') { "$n $t " + [bool][Environment]::GetEnvironmentVariable($n, $t) } }
   [bool](Select-String -Path .env -Pattern '^\s*ANTHROPIC_(API_KEY|AUTH_TOKEN)\s*=\s*\S' -Quiet)
   ```
   Везде должно быть False. Если где-то True, скажи владельцу: пусть удалит переменную в
   переменных среды Windows (поиск в Пуске: «переменные среды») или строку в `.env`, потом
   выйдет из Windows и войдёт снова. Сам ничего не удаляй.

   **Вход.** Владелец входит сам, ты за него не войдёшь. Попроси его открыть PowerShell и
   выполнить `& "$env:USERPROFILE\.local\bin\claude.exe" auth login`: откроется браузер, там
   войти аккаунтом с платной подпиской Claude. Дождись, пока он скажет, что вошёл, и проверь:
   ```powershell
   & "$env:USERPROFILE\.local\bin\claude.exe" auth status --text
   & "$env:USERPROFILE\.local\bin\claude.exe" -p "Reply with one word: works" --model claude-opus-5-5 --tools=
   ```
   Пустой список инструментов пиши как `--tools=`: PowerShell 5.1 выбрасывает из команды `""`.
6. Slack, время и словарь. Программа присылает результат от имени бота в канал владельца.
   В `.env` будет токен, поэтому файл целиком не читай и не открывай своим инструментом
   редактирования. Значения вписывай командой ниже (определение функции и вызов — одной
   командой; `<КЛЮЧ>` и `<значение>` подставь). Она меняет значение в строке, которая уже
   есть, а если строки нет, добавляет её: вторая такая же строка ниже первой не сработала бы.
   ```powershell
   function Set-Env($k, $v) { $f = Join-Path $PWD ".env"; $t = [IO.File]::ReadAllText($f); $p = "(?m)^[ \t]*$k[ \t]*=[^\r\n]*"; if ($t -match $p) { $t = $t -replace $p, "$k=$v" } else { $t = $t.TrimEnd() + "`n$k=$v`n" }; [IO.File]::WriteAllText($f, $t, (New-Object Text.UTF8Encoding $false)) }; Set-Env <КЛЮЧ> <значение>
   ```
   Что получилось, смотри без токена:
   `Get-Content .env -Encoding UTF8 | Select-String '^\s*(SLACK_CHANNEL|SLACK_NOTIFY_USER|HUDDLE_TIMEZONE|HUDDLE_GLOSSARY)\s*='`.
   Порядок важен: токен — последним. С токеном, но без канала наблюдатель не запускается (в
   логе `SLACK_BOT_TOKEN and SLACK_CHANNEL are needed`); без токена работает, но результаты
   только в «Результатах».
   - **Свой канал у каждой установки.** Если `SLACK_CHANNEL` уже заполнен и это не
     `C0CEZN01JTV`, пункт пропусти. Иначе спроси у владельца ID его канала: в Slack нажать на
     название канала, ID внизу окна («Channel ID», вида `C0123ABC`). Это не секрет:
     `Set-Env SLACK_CHANNEL <ID>`. Канал `#call-recaps` (`C0CEZN01JTV`) занят другой
     установкой; если владелец даёт его, объясни, что нужен свой. Программа читает ответы
     под сообщениями своего бота о звонках в канале, чьи бы они ни были: две установки с одним
     ботом в одном канале записывали бы чужие ответы себе в пожелания и обе отвечали бы в
     треде. Если своего канала у владельца пока нет, дальше шага 6 не иди, пока он его не
     заведёт.
   - **Бот в канале.** Владелец пишет в своём канале `/invite @ai-recap` (или имя своего
     бота). Если бота в канале нет, сообщения туда не дойдут.
   - **Кого отмечать.** Спроси у владельца его Slack ID: свой профиль в Slack → «⋮» → «Copy
     member ID» (вида `U0123ABC`), и `Set-Env SLACK_NOTIFY_USER <ID>`. Бот отмечает владельца
     в сообщении о каждом звонке и в сообщении об ошибке. Без ID сообщения приходят без
     отметки.
   - **Часовой пояс.** По `HUDDLE_TIMEZONE` пишется время звонка в файле и в его имени. Стоит
     `Europe/Chisinau`; если владелец в другом поясе: `Set-Env HUDDLE_TIMEZONE Europe/Berlin`
     (свой пояс).
   - **Словарь.** `HUDDLE_GLOSSARY=староста` — словарь планёрок команды Zinrai: проекты, имена,
     термины. Whisper получает его как подсказку, а Claude исправляет по нему ошибки
     распознавания, поэтому чужой словарь вредит. Спроси владельца, из этой ли он команды.
     Если нет, составь с ним свой: `данные\glossaries\<имя>.txt` (имя — буквы, цифры, `_` и
     `-`), одна-две строки о том, что за звонки, и списки проектов, имён и терминов, как в
     `староста.txt`; потом `Set-Env HUDDLE_GLOSSARY <имя>`.
   - **Токен.** `SLACK_BOT_TOKEN` владелец вписывает сам, не через чат: открывает `.env` в
     Блокноте, вписывает токен в ту же строку сразу после `SLACK_BOT_TOKEN=` и сохраняет.
     Токен готового бота `@ai-recap` он получает у разработчика лично; токен своего
     приложения Slack — на его странице: OAuth & Permissions → Bot User OAuth Token. Проверь
     (печатается только True или False):
     ```powershell
     $l = Select-String -Path .env -Pattern '^\s*SLACK_BOT_TOKEN\s*=' | Select-Object -First 1; [bool]($l -and $l.Line -match '=\s*["'']?xoxb-')
     ```
7. Автозапуск наблюдателя при входе в Windows:
   ```powershell
   $root = (Get-Location).Path
   $exe = Join-Path $root "программа\.venv\Scripts\huddle-notes.exe"
   $log = Join-Path $root "данные\logs\watch.log"
   $action = New-ScheduledTaskAction -Execute "powershell.exe" -WorkingDirectory $root `
     -Argument "-NoProfile -WindowStyle Hidden -Command `"& '$exe' --log '$log' watch`""
   $trigger = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
   Register-ScheduledTask -TaskName "Call Recaps" -Action $action -Trigger $trigger `
     -Settings (New-ScheduledTaskSettingsSet -ExecutionTimeLimit 0 -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries)
   Start-ScheduledTask -TaskName "Call Recaps"
   ```
   Проверь, что в `данные\logs\watch.log` появилась строка `watching ...\Записи`. Потом
   `программа\.venv\Scripts\huddle-notes.exe notify-test` и спроси владельца, всплыло ли в углу
   экрана уведомление «Проверка уведомлений». Без `-AllowStartIfOnBatteries` и
   `-DontStopIfGoingOnBatteries` Windows не запускала бы задачу на ноутбуке от батареи и
   останавливала бы её, когда ноутбук отключают от сети.
8. OBS: Настройки → Вывод → Путь записи → папка `Записи` этой папки. Формат mkv или mp4.
   Источник — «Захват окна» на окно хадла Slack, плюс звук рабочего стола и микрофон.
   Если в OBS включена автоматическая перепаковка записи в MP4 (расширенные настройки,
   раздел про запись), выключи её: иначе в «Записях» окажутся два файла одного звонка, и сообщений
   придёт два. Скажи владельцу, что запись нельзя ставить на паузу: паузу дольше полуминуты
   программа может принять за конец, и заметки будут только по части до паузы (второе
   сообщение после остановки — с той же частью). Пересчитать весь звонок: удалить
   `данные\work\<имя записи без расширения>\audio.wav` и `words.json` там же и обработать
   запись вручную («Обработай запись» ниже).

## Проверка

Положи в «Записи» короткую запись хадла (5–10 минут). Через минуту в логе должно быть
`processing ...`, а в углу экрана — уведомление «Взял в работу» с именем файла. Потом в
«Результатах» появится файл, а в Slack — сообщение. В нём не должно быть «Заметки не
получились», а под названием — имя файла этой записи. Покажи владельцу время обработки из
лога и заметки. Подписей, кто говорит, в расшифровке нет — так задумано.

## Что делать по просьбам владельца

- **«Обработай запись» вручную.** Найди запись в «Записи» (по журналу) и запусти:
  ```powershell
  программа\.venv\Scripts\huddle-notes.exe process "Записи\<запись>" --notify
  ```
  Ручная обработка журнал не трогает. Если этой записи в журнале нет или она там не доведена
  до конца (упала меньше трёх раз, не отправлена, без заметок), наблюдатель обработает её сам
  и пришлёт второе сообщение. Чтобы этого не было: сначала `Stop-ScheduledTask -TaskName
  "Call Recaps"` (работающий наблюдатель перезапишет журнал), потом обработка, потом в
  `Результаты\.huddle-notes-journal.json` у этой записи: `status` "done", `attempts` 0,
  `delivered` true, `notes_error` null, `retry_after` null, `size` — текущий размер файла
  записи; потом `Start-ScheduledTask -TaskName "Call Recaps"`.
- **Вопросы по звонкам** («что поручили Жене?», «где говорили про iOS?»): ищи в файлах
  «Результатов», отвечай со временем из расшифровки. Помни, что расшифровка бывает неточной и
  в ней не подписано, кто говорит: называй человека, только если это видно из самого текста.
- **«Включи имена»** (кто какую реплику сказал): это владелец решает вместе с разработчиком.
  `Set-Env HUDDLE_SPEAKERS on` (команда из шага 6), потом модели (шаг 4) и перезапуск задачи
  «Call Recaps». Без базы лиц в `данные\people` программа сначала никого не узнаёт.
- **Пожелание к заметкам** («пиши короче», «задачи всегда с датами»): допиши в конец
  `данные\пожелания.md` строку в том же виде, что и остальные:
  `- ДД.ММ.ГГГГ, <кто> (Claude Code): <пожелание>`. Если файла нет, создай его с заголовком
  `# Пожелания к заметкам`. Правь файл своим инструментом редактирования, в UTF-8, не через
  `Add-Content`. Покажи владельцу итоговый список. Действует со следующего звонка.
- **Словарь** («добавь в словарь <название>», «Whisper путает название проекта»): файл
  `данные\glossaries\<имя из HUDDLE_GLOSSARY>.txt` — короткий текст с проектами, именами и
  терминами команды. Whisper получает его как подсказку и лучше слышит эти слова; Claude
  тоже получает его вместе с расшифровкой. Правь файл своим инструментом редактирования, в
  UTF-8: в другой кодировке наблюдатель не запустится. Наблюдатель читает словарь при
  запуске, поэтому новый действует после перезапуска задачи «Call Recaps»: останови её и
  проверь, что программ из `.venv` не осталось (как в «Обнови программу»), потом
  `Start-ScheduledTask -TaskName "Call Recaps"`. Проверь, что в `данные\logs\watch.log`
  появилась новая строка `watching ...\Записи`. Если её нет: строка `no glossary …` — нет
  файла или неверное имя в `HUDDLE_GLOSSARY`; лог просто оборвался — файл не в UTF-8.
- **«Покажи пожелания», «убери это пожелание»:** пожелание — строка, начинающаяся с «- », в
  `данные\пожелания.md`; удаляй только то, что владелец назвал. В заметки идут 40 последних.
- **Расшифровка не на том языке** (например, звонок шёл на двух языках): программа определяет
  язык по трём кускам с 20, 50 и 80 % записи, тишина в начале ей не мешает. На каком языке
  расшифрован звонок, видно в логе в строке `<запись>: language ru, … words`. Чтобы пересчитать
  такой звонок, удали
  `данные\work\<имя записи без расширения>\words.json` (если такой папки нет, это та, где в
  `document.txt` стоит имя файла звонка в «Результатах») и обработай запись вручную (см. выше),
  задав язык только для этой команды:
  ```powershell
  $env:HUDDLE_WHISPER_LANGUAGE = "en"; программа\.venv\Scripts\huddle-notes.exe process "Записи\<запись>" --notify; Remove-Item Env:HUDDLE_WHISPER_LANGUAGE
  ```
  В `.env` язык не закрепляй, если владелец не просит: звонок на другом языке тогда
  расшифруется с потерями.
- **Что-то не работает:** смотри `данные\logs\watch.log` и журнал в «Результатах».
  Всё про отзывы из Slack — строки со словом `feedback`.
- **Нет уведомления «Взял в работу»:** в логе при запуске наблюдателя должна быть строка
  `notifications on screen: on`, а при взятии записи — `processing <запись>`. Строка
  `notification failed: …` значит, что Windows уведомление не приняла: покажи владельцу её
  текст. Запусти `программа\.venv\Scripts\huddle-notes.exe notify-test`. Если команда пишет
  `sent to Windows`, а в углу экрана пусто, посмотри с владельцем центр уведомлений (Win+N, в
  Windows 10 — Win+A): при режиме «Не беспокоить» уведомление сразу ложится туда. Если и там
  нет, уведомления выключены в Параметры → Система → Уведомления (в Windows 10 — «Уведомления
  и действия»): общий переключатель или для «Call Recaps». Если уведомления включены, а
  пробного нет ни в углу, ни в центре уведомлений, Windows, видимо, молча не принимает имя
  «Call Recaps»: выполни `Set-Env HUDDLE_DESKTOP_NOTIFY powershell` (команда из шага
  6), перезапусти задачу «Call Recaps» и
  снова `notify-test`. Тогда в заголовке будет «Windows PowerShell», текст тот же. Так же
  выглядит уведомление, если имя не удалось записать в реестр (в логе строка
  `notifications go under Windows PowerShell's name`). `Set-Env HUDDLE_DESKTOP_NOTIFY off`
  выключает уведомления совсем.
- **«Заметки не получились» с `Login expired`:** вход в `claude` истёк. Владелец снова
  выполняет `claude auth login` (шаг 5). Заметки к этому звонку придут сами: программа
  просит их заново раз в 30 минут, всего 12 попыток (около 5,5 часа).
- **«Обнови программу из папки <путь>»** (владелец распаковал архив «Обновление Call Recaps
  <дата>», например «Обновление Call Recaps 2026-11-12»:
  в нём `программа\` и `CLAUDE.md`). Сначала прочитай `CLAUDE.md` из этой папки: в новой версии
  могут быть свои шаги. Потом из корня Call Recaps; каждый блок — одной командой:
  ```powershell
  Stop-ScheduledTask -TaskName "Call Recaps"
  $venv = (Resolve-Path программа\.venv -ErrorAction Stop).Path
  Get-Process | Where-Object { $_.Path -like "$venv\*" } | Select-Object Id, Name
  ```
  Список программ из `.venv` должен быть пустым; если нет, останови их (`Stop-Process -Id <Id>`),
  иначе установка не сможет заменить `huddle-notes.exe`. Потом, подставив в `$src` папку, где
  лежат `программа` и `CLAUDE.md` (Windows при распаковке часто кладёт её в одноимённую папку):
  ```powershell
  $src = "<папка обновления>"
  Copy-Item -Recurse -Force "$src\программа\*" программа\
  Copy-Item -Force "$src\CLAUDE.md" .
  cd программа
  uv pip install --python .venv\Scripts\python.exe --reinstall-package huddle-notes .
  cd ..
  программа\.venv\Scripts\huddle-notes.exe models download
  Set-ScheduledTask -TaskName "Call Recaps" -Settings (New-ScheduledTaskSettingsSet -ExecutionTimeLimit 0 -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries)
  Start-ScheduledTask -TaskName "Call Recaps"
  ```
  `Set-ScheduledTask` даёт задаче настройки из шага 7, если она поставлена раньше: на ноутбуке
  она тогда работает и от батареи.
  `models download` докачивает модели, которых не хватает новой версии; у уже скачанных
  сверяет контрольные суммы (это минута-две) и перекачивает только испорченные. Если он
  упал (нет интернета), запусти его ещё раз и перезапусти задачу «Call Recaps»: без модели
  VAD программа работает, но в логе будет строка `no VAD model`, а Whisper может зациклиться
  на долгой тишине.
  Проверь, что в `данные\logs\watch.log` появилась новая строка `watching ...\Записи`. Потом
  `программа\.venv\Scripts\huddle-notes.exe notify-test` и спроси владельца, всплыло ли в углу
  экрана уведомление «Проверка уведомлений»; если нет, см. «Нет уведомления» выше.
  `.env`, `данные\`, «Записи» и «Результаты» обновление не трогает. Если в `данные\people`
  лежит старая база лиц и голосов, а имена выключены, она не используется; удаляй её, только
  если владелец попросит.

## Правила

- Записи, расшифровки, лица и голоса никуда не отправляй, кроме Slack-сообщения программы.
- `.env` целиком не читай и не показывай: в нём токен. Значения меняй командой `Set-Env`
  из шага 6, смотри только нужные строки без токена.
- Не меняй код в `программа\`, пока владелец явно не попросит.
